# 机制分析与构建

从论文的具体设计中分析作用逻辑，抽象可复用思想，比较不同实现，并构建、更新有证据与适用边界的机制知识卡，为后续 Idea 推理提供依据。Agent 主动完成这些分析；研究者的见解是重要输入，并可在过程中讨论、修正关注方向。

## 输入、入库条件与目录

使用用户指定或会话已明确的研究工作目录；不能将 Skill 源码仓库当作研究目录。机制卡保存为 `工作目录/mechanisms/机制名称.md`，来源论文通常位于 `references/论文标题/paper.md`。只在需要保存真实内容时创建目录。

新论文进入机制库必须同时满足：研究者已补充其见解，Agent 已结合这些见解完成再次分析。检查当前论文说明的人工观点及相应分析，不把非空标题或初稿中的 Agent 设想视为已完成。状态记录仅作辅助；研究者后续又修改见解时，旧记录不代表最新内容已分析。

条件未满足的论文不用于新增或补充机制结论，指出缺少的步骤；可继续处理其他已就绪来源。维护已有机制方向时无需重新导入全部论文，但新增来源仍须满足入库条件。不以整理机制为由擅自代写研究者观点。

## 主流程：机制分析、构建与增量更新

1. 读取本次已就绪的论文说明，重点理解模型机制、消融、值得关注的设计、迁移思想及研究者观点与 Agent 分析。通过标题、正文关键词和已有链接定位相关机制，按需读取相关来源；有疑点才回查原文。
2. 识别并抽象候选机制：具体设计针对什么问题，改变了什么表示、关系或处理过程，怎样影响信息利用，承担什么功能。分清可保留的思想、可替换的实现和必要依赖；抽象后仍应能对应到原设计，避免只给模块换名或提取宽泛标签。作用解释区分原文依据与 Agent 推断。
3. 比较已有相关实现：建模对象与关系语义、信息组织方式、作用位置、训练约束及成立条件。判断哪些是共同思想、哪些差异会改变功能或使用边界。模块同名不代表机制相同，名称不同也可能具有共同思想；不要为归类抹去关键差异。
4. 构建或更新下述五部分机制卡，明确核心思想、来源差异、适用边界、证据和未解问题。只有独立保存能帮助后续理解、比较或迁移时才新增卡片；不按每个模块机械拆文件。单篇已就绪论文也可形成卡片，但不虚构跨论文共识。
5. 增量维护：根据新认识补充实现、修正解释或边界，保留差异与冲突。普通证据补充可直接更新；涉及既有核心思想或研究者方向约定的改变，按下述协作规则讨论。没有实质新增时简述原因，不重写整卡。
6. 在来源论文说明的“知识库关联”中维护指向机制卡的链接，保留已有内容；机制卡链接回具体论文说明章节。重命名时同步修正工作目录内相关链接，避免生成平行版本。上述分析过程用于形成卡片，不另外输出重复报告。

## 分析过程中的研究者参与

研究者可以随时指出理解偏移或提出更有价值的机制方向，不必先写完整文档。结合机制卡与来源，理解其希望改变的核心思想、抽象粒度、关注对象或迁移方向；简短说明分歧、具体改法、依据与疑点，不只复述或附和。

改变既有核心思想、命名含义、拆分或合并机制时，讨论确定后再更新当前结论；未确定方案在对话中作为候选，保留原卡。已有明确意见直接落实，不重复确认；其余分析工作正常推进。研究者选择关注方向，原文事实仍须核实，证据不足的解释保留为分析或假设。

确定后重新审视第1—4节，必要时调整名称与关联，避免仅追加回应而留下冲突正文。保留研究者原话或原始记录链接，另记确定的方向、日期、变化及原因；未采纳方案仅在有助于恢复研究时简记理由。

## 机制卡结构

标题围绕一个能独立解释与比较的机制命名，避免只有宽泛技术标签；保留有用的既有名称，避免纯措辞变化导致频繁改名。正文采用已约定的五部分：

1. **核心思想**：针对的问题、怎样发挥作用、最值得保留的设计。保持具体，不只写“捕获高阶关系”等概括。
2. **来源实现与差异**：链接来源论文说明，简述相关实现及影响理解或使用条件的关键差异。可用小表，列按比较需求选择，不复制完整架构与实验表。
3. **适用条件与迁移边界**：所需数据或模型条件、可替换实现、必须保留的依赖，以及改变对象或作用位置后需验证的问题。
4. **证据与待解决问题**：现有证据的支持范围，研究者启发、Agent 推断及来源间冲突。消融结果留在对应架构条件下，不推成机制普遍有效；不同论文指标不直接作效果排名。
5. **关联与重要修订**：已有机制或 Idea 链接，以及研究者方向约定、重要变化和原因。没有相关内容时可省略，不记录完整聊天或每次措辞调整。

来源只有一篇时只陈述该来源及分析，不编造共同原理。事实、研究者启发与 Agent 推断就近区分并保留定位，避免堆砌统一免责声明。没有实现过的迁移仍是待验证设想。

## 精简与交付

优先增量修改，先检索再定向读取，不重读整个知识库。正文保存综合认识与差异，细节链接回论文说明；不要求填满篇幅或创建额外索引、比较报告和日志。

交付前检查入库条件、来源与反向链接、事实与分析边界、正文一致性，以及重要方向变化是否已有研究者明确意见。发现来源认识修正时更新受影响的机制；涉及既有 Idea 仅说明潜在影响，不自动修改其核心方案。聊天只报告新增或修改的文件、主要认识变化和需要继续讨论的问题。
