# 实验结果记录与原因分析

只在整理实际实验材料时读取。沿用主 Skill 的研究者意见与决策规则。

1. 在目标 Idea 的 `experiments/` 下查找本次实验；需要新建时分配未用的 `EXP-001-实验名称/`，用一份 `experiment.md` 汇总设置、结果与分析。没有材料时不虚构结果，不自动运行训练。
2. 说明实验问题、对应架构版本、实际改动或代码版本；记录已知的数据集与划分、关键参数、随机种子和评价设置。缺失内容注明未提供，不把当前方案误当成过去实验所用版本。
3. 保留真实数值与来源，保存用户提供的表格、图或日志，或链接到可访问的原始材料。不强制复制大型数据、权重或代码库，不重复输出完整日志。负结果和失败记录同样保留。
4. 分开写观察、可能原因和待核实线索，结合设置差异、实现情况和模块交互解释。比较前检查条件是否可比，不将推测写成已证实因果，也不把缺失值补成结果。
5. 从 `idea.md` 链接实验分析。研究者据此决定调整架构时，再同步正文与 `decisions.md`，关联实验依据；Agent 的建议保持为建议。

记录应足以帮助后来理解实验发生时的条件。图、日志与数值互有出入时保留并指出差异，不自行挑选有利版本。交付时只概括关键发现、记录路径及必要缺口。
