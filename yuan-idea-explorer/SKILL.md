# Idea 与模型架构探索

拓展研究者的设计空间，提供不易立即想到的模块和架构，供研究者选择、组合和删减。允许借鉴、重组已发表方法，也鼓励改变建模对象、作用方式与模块交互。默认充分展开有启发性的结构；有效性判断与取舍由研究者主导。

## 研究输入

- 使用用户指定或会话已明确的研究工作目录。未明确保存位置时先询问，不能写入 Skill 源码仓库；仅讨论而不保存时无需确定目录。
- 优先读取 `research-context.md`、本次研究者想法和指定论文，再按需检索相关机制与已有 Idea。研究者可以只提供“两三篇论文可能可以结合”的直觉，无需先组织成完整研究问题或创新论证。
- 组内未发表 base 是可选、可质疑、可完全放弃的参考。以研究任务及明确约束为依据，不默认保留其框架或模块；已发表论文的具体方法按来源核实，也不把其结论自动推成新组合有效。
- 参考资料可以来自论文说明、机制卡或用户提供的原文。机制库不是探索的必经关卡，不要求每个拟借鉴设计先建立机制卡。直接使用论文不会自动生成机制卡；需要机制构建时按相关任务处理，不以人工补充或再次分析为前提。
- 保留已有研究者观点，区分明确要求、方法偏好和探索性设想。缺少非关键条件时标明假设继续探索，不为凑背景编造数据、资源或已确定方案；只有缺失信息确实影响研究方向时才定向询问。

## 按任务选择范围

| 当前任务 | 读取与产出 |
| --- | --- |
| 仅讨论 | 根据问题读取必要材料，直接讨论，不强制建档或输出完整八部分。 |
| 新建候选架构 | 查索引避免重复，使用下述脚本建档，完整展开主文档。 |
| 延续或局部修改 | 先定位目标，读取当前方案，再按问题读取相关决策与章节；只修改受影响内容，同步相关图示、训练描述和记录。 |
| 整理实际实验 | 先读 [实验记录细则](references/experiment-recording.md)，再读取该次材料和对应架构，不加载无关历史。 |

首次纯讨论不强制落盘；用户要求保存或任务包含建档、更新时维护文档。已明确持续维护的 Idea，其后续反馈与决定按更新任务处理，无需用户反复说“保存”。分流不限制设计深度，局部修改不重复生成完整方案。

## 探索过程

1. 理解研究者关注的设计空间和参考方法的可借鉴之处，梳理它们可能承担的功能。问题可以随着架构探索逐步清晰，不要求先提出完整理论或确定单一瓶颈。
2. 尝试具体实现借鉴、模块重组、建模对象改变、功能迁移及思想重构。探索多关系、多粒度、多阶段或跨模块交互等组织方式，但选择应来自当前材料和想法，不按固定技术清单堆叠。
3. 主动发展新模块：说明表示什么、如何构造关系或执行操作、信息怎样流动，以及和其他模块怎样交互。新名称必须对应具体设计；需要时用关键公式表达新操作，避免只列模块名和泛泛功能。
4. 组织整体架构，展开输入、分支、层次、融合、输出及训练目标之间的联系。允许较丰富的内部结构与多种训练信号；交代其组织方式以便研究者理解和改造，不以先做最小版本或减少模块数为默认目标。
5. 有不同探索方向时形成结构有实质差异的候选，按内容决定数量，不强制生成多份。相同架构下的局部变体先在同一 Idea 中展开。不要在研究者判断前自动评分、淘汰方案或将候选简化成保守版本。

说明哪些设计借鉴、改变或新提出，来源链接到相关论文或机制。预期作用可以作为设计假设简明解释；未经实验不承诺有效，未做相关工作核验不宣称“首次”或“无前例”。这些证据边界不应扩展成逐模块的风险清单或严格评审。用户后续明确要求评估、简化、实现或实验设计时，再按该任务处理。

## 工作目录与文件

项目基础结构由 `yuan-project-init` 创建，不在这里重复实现。`research-context.md` 保存背景与明确约束，只按实际输入更新；不把候选架构写成既定背景。

按需选择对应子命令，使用已有 Python 运行本 Skill 的脚本，`SKILL_DIR` 替换为本文件所在的实际绝对路径：

```bash
python "SKILL_DIR/scripts/idea_files.py" create "/研究工作目录" --title "方向名称"
python "SKILL_DIR/scripts/idea_files.py" snapshot "/研究工作目录/ideas/IDEA-001-方向名称"
```

`create` 要求项目已有 `ideas/INDEX.md`，分配未用编号并创建 Idea 目录、[薄模板](assets/idea.md)生成的 `idea.md`、空 `decisions.md` 与预留 `experiments/`。它不会生成研究内容或更新索引；已有同名方向报错，Agent 先判断是继续原方向还是使用有区别的名称。`snapshot` 原样保存当前主文档到下一个未用的 `versions/v001.md`，不改原文。检查退出码与 JSON 的 `ok`；调用时无需将源码读入上下文，结果仅返回路径与状态。

Agent 负责填写主文档、决策和 `ideas/INDEX.md`：索引每行记录编号、名称、一句话核心构想、状态、主文档链接。新方案为候选，其余状态依研究者意见，不自动选定方案。每条独立架构一份主文档，局部变体保留在其中；延续方向保留编号与目录。脚本成功只表示建好骨架或快照，完成正文与必要决策、索引同步才算完成建档或更新。

参考论文与机制只链接；架构图优先嵌入 Markdown，确需图片时再建 Idea 的 `assets/`。无实验时不生成结果文件。

## Idea 主文档结构

开头注明编号、候选状态和必要的分支来源，标题概括方向。采用以下八部分：

1. **核心构想**：架构围绕什么思路展开，最值得关注的设计是什么。
2. **启发来源与设计转化**：论文、机制及研究者直觉的来源，分别保留、改变或重新组织了什么。
3. **整体架构与信息流**：给出结构图（如 Mermaid）及必要解释，明确数据进入、分支处理、交互和预测输出；图与文字保持一致。
4. **关键模块设计**：逐个展开设计动机、建模对象、输入、内部操作与输出。将篇幅优先用于有启发性的新设计和关键改造，不反复复述已有模块。
5. **模块交互与训练组织**：信息如何传递或共同学习，训练目标作用于哪里、如何联系各部分。尚未确定的细节说明候选设计或假设，不冒充已经实现。
6. **可继续探索的变化**：不同实现、替代结构或延伸，以及各自带来的设计空间。保留值得讨论的复杂变化，不默认只给简化方案。
7. **研究者意见**：保留研究者原话或原始记录链接，未提供时注明待补充；Agent 的解读放在对应分析或演化记录中，不冒充研究者判断。
8. **讨论与演化记录**：简短概括当前演化脉络，链接 `decisions.md` 中相关记录及已有实验分析；完整决策和实验内容各保留一处，没有讨论时只注明本次初始候选。

第3—5节是主要产出，可按设计复杂度充分展开，不套用论文说明的字数目标。默认不增加评分、严格有效性审核、最小版本或完整实验计划章节。

## 持续讨论与更新

收到反馈后重新理解研究者意图，修改受影响的架构、模块、训练组织和图示，不能只追加回应而留下冲突正文。研究者明确的要求直接落实；方向有实质歧义时说明具体差别再讨论。新论文带来的替代架构作为候选或分支，不自动覆盖研究者已选方案。

局部调整更新原 `idea.md`，保留研究者原文。大幅改写前调用 `snapshot`，在对应决策中链接返回的旧版；形成独立方向时调用 `create`，记录分支来源，不覆盖已选方案。不为每次措辞调整存快照。

## 决策历史与研究恢复

`idea.md` 保存当前方案，`decisions.md` 保存方案为何发展至此。重要的模块引入或删除、建模对象或训练方式改变、方向取舍及分支建立，都应及时记录；普通措辞调整不记决策。

每条记录采用未用的 `D001` 等编号和简短主题，包含日期、讨论的问题、主要备选与依据、当前决定及其状态、影响与后续。关联论文、实验或旧版作为依据。研究者明确决定与 Agent 建议分开，尚未确定时标为待讨论；未提供的理由不代为编造。

历史判断变化时新增记录，说明新依据和替代关系，在旧记录上标注被哪条记录更新，不悄悄改写过去。落实研究者决定时同步更新架构正文及索引。

新会话先通过索引定位目标 Idea，读取 `idea.md`，再按当前问题查看相关决策、实验和来源，恢复已考虑的方案与未解问题。不要无依据地再次提出已否决方向；新证据足以重新讨论时说明原因。记忆主要保存在各 Idea 文件中，无需额外创建 `NOW.md`。

实际实验须关联当时的架构或代码版本，保留真实结果，区分观察与原因推断；分析建议不自动成为研究者决定。具体文件组织与检查只在实验任务中读取上述细则。

## 精简与交付

材料定向读取，优先复用可信说明；对关键模块深入设计，对常规背景简洁交代。不用大量模板化文字或重复文件制造丰富感，不以控制 Token 为由压缩关键新设计。

交付前检查结构图、模块接口与训练描述是否相互一致，来源及决策、实验链接是否可定位，研究者原文与旧架构是否按需保留，索引是否反映实际文件与研究者决定。检查的目的在于准确表达候选与已有证据，不替研究者裁定方案取舍。聊天只概括关键设计或认识变化、文件位置及待讨论选择，不重复整份文档。
