# 研究项目初始化

将研究流程落地到用户指定的真实工作目录。使用配套脚本创建结构，不临时重写初始化逻辑。

## 执行

确认用户指定或会话已明确的目标目录；没有明确位置时询问。将 `SKILL_DIR` 替换为本文件所在目录的实际绝对路径，使用已有 Python 3.10+：

```bash
python "SKILL_DIR/scripts/init_project.py" init "/绝对路径/研究项目"
```

脚本默认通过自身位置查找同级的三个研究 Skill，生成项目级 AGENTS.md 中的实际链接。若它们位于其他目录，使用 `--skills-root "/包含三个Skill文件夹的目录"`。该路径缺少所需 Skill 时报告错误，不安装或猜测路径。

需要只查看计划时加 `--dry-run`，目标目录也不会创建。检查退出码和 JSON 的 `ok`，失败时依据错误修正，不以删除或覆盖已有文件解决冲突。

## 产物与保留规则

```text
工作目录/
├── AGENTS.md
├── research-context.md
├── references/
├── mechanisms/
└── ideas/
    └── INDEX.md
```

首次创建轻量背景模板与空索引，不预填研究事实或创建候选 Idea。项目级 AGENTS.md 只记录资料职责、Skill 入口和维护原则，具体分析要求留在各 Skill 内。

已有研究背景、索引、论文和 Idea 均保留。已有 AGENTS.md 时追加一次带标记的项目说明块，原文不变；已有该块则保留，包括人工修改，不静默刷新。脚本报告该块与当前模板不同时，查看实际差异后再按用户需要维护，不自动替换。遇到受管路径类型冲突、符号链接或损坏标记时，在写入前报错。

初始化不自动创建 `NOW.md`、具体论文/机制/Idea、实验结果或 Git 仓库；相应内容在实际研究时生成。脚本不安装依赖或修改系统设置。

交付时简述实际目标路径、创建/追加/保留情况和需要处理的冲突。初始化后按研究任务使用对应 Skill，不将空模板描述成已完成研究分析。
