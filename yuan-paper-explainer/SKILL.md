# 参考论文说明

让后续研究能够准确理解论文模型、识别值得借鉴的设计，并按证据位置回查原文。默认面向下一 POI 推荐及相关图、超图、知识图谱方法，用户指定其他领域时按论文实际内容分析。

## 工作目录与论文材料

使用用户指定或当前会话已明确的研究工作目录；未明确时先询问保存位置，不能把 Skill 源码仓库当作研究目录。只回答局部问题且不保存文件时，无需先确定目录。

默认结构为 `工作目录/references/论文标题/`，其中 `paper.md` 为唯一主说明，`paper.pdf` 为原文副本。目录不存在时创建；标题仅清理不适合路径的字符，过长时适度缩短。同名不同论文再补作者或年份。

- 先根据已有来源记录中的 Zotero 条目 key、DOI 或标题查找同一论文，命中后复用目录与说明。已知有旧说明时一并核对，避免因标题差异另建一份；需要调整旧布局时保留人工内容并修正相关链接。
- 从用户 PDF 或 Zotero 附件复制原文，不移动或修改源文件；已有同版本 PDF 时复用。版本不同或无法确认时先说明差异，不静默覆盖。
- 说明开头简列已知作者、年份、论文版本与来源标识，并用 `[原文 PDF](paper.pdf)` 链接本地副本。复制后确认文件可读；无法取得 PDF 时如实注明缺失，不生成虚假的本地链接。

## 执行模式

- **首次生成**：阅读原文并完成下述分析，第3、4节为初步判断；第6节留给研究者填写，第7节按已有人工观点分析，没有则保留占位。先交付初稿，不等待人工补充。
- **补充后再分析**：用户填入或修改第6节后，重新读取整份 `paper.md`，理解其观点与原有说明的联系，按疑点定向回查 `paper.pdf`。重新审视第3、4节，并在第7节解释依据、成立条件、疑点与延伸；必要时修正第2、5节。不能仅追加第7节而跳过对第3、4节的重新审视，也不为了体现更新而强行改动仍成立的判断。

再次分析时保留研究者原始文字，优先修改同一文件中的相关内容，不重读无关材料或生成整份平行版本。研究者设想不直接作为论文事实；观点与原文不符时在 Agent 分析中说明依据。重要判断变化时在文末简记日期、变化与原因，不记录每次措辞调整。

首次保存时简记状态“初稿，待研究者补充”；结合研究者实际见解完成再次分析后更新为“已结合研究者见解再次分析”并注明日期。只有完成这两个步骤的论文才可进入机制库；本 Skill 不在初稿阶段自动生成机制卡。后续见解改变时需重新分析，不能沿用旧状态判断已就绪。

## 读取与证据

- 优先使用用户提供的原文和可信提取结果；确认论文版本。旧笔记与研究者观点作为线索，模型事实回到原文核实。
- 先定位方法、框架图、关键公式及消融实验；背景与其他实验仅在解释模型或判断消融所需时读取。不重复生成全文翻译或完整实验综述。
- PDF 可先提取文本；结构、公式或表格有歧义时查看相关页面。局部读取不能省略关键分支、训练目标或决定模块作用的内容。
- 关键模型说明和消融判断附近保留章节、图、表或公式定位；有可靠页码时区分 PDF 页与印刷页。不得猜测页码、数值或未提供的模块。
- 若只有摘要或局部材料，明确说明范围，仅输出可支持的部分和关键缺口；不要补齐未知架构。无法访问原文时说明缺少什么材料。

## 分析流程

### 1. 客观模型还原

以“输入 → 处理与分支 → 交互或融合 → 预测输出”梳理整体数据流；并行模块不要强行写成串行。

说明各关键模块处理什么信息、完成什么功能、输出如何被使用。对图方法明确节点、边或超边表示什么、如何构造，以及必要的信息传播过程。交代训练目标如何作用于模块。

梳理到能够解释模型如何运转即可。公式、维度和实现细节仅在影响理解时保留，不逐一复述。尚不清楚的连接或构造方式直接标明。

### 2. 消融实验

确认各变体实际删除、替换或改变了什么，比较对象是什么。结合所报告的数据集和指标，判断模块在当前架构下的作用。

- 保留足以支持判断的关键结果或相对排序，不整表搬运。数值变化需说明方向，百分比与百分点不要混用。
- 关注贡献明显、贡献有限、跨设置不一致，以及移除后反而改善的设计；不要只选择有利结果。
- 联合移除多个设计不能分配各自贡献；缺少单独消融时说明无法独立判断。未报告显著性时不使用统计显著或无差异的结论。
- 消融反映所测试架构与条件下的表现，不能单凭性能下降证明作者解释的作用机制，也不能把小幅贡献直接称为无效。
- 未提供消融时简述“未见可用消融证据”，不自行推演结果。

### 3. 识别与抽象

从实际结构和消融中选择少量值得关注的设计，说明“针对什么问题 → 具体改变什么 → 如何发挥作用 → 证据与限制”。区分作者的解释和 Agent 的分析；反事实推断写成推断。

抽象时保留具体建模对象、关系语义或信息组织方式，避免只有“捕获高阶关系”“融合多源信息”等泛泛表述。指出可保留的思想、可改变的实现和必要条件。

没有用户研究基座时，将迁移方向写为条件性设想，不强行设计新框架。作者宣称创新、论文具体特点和领域新颖性分别判断；未做相关工作核验时不宣称领域首次。

### 4. 研究者参与

根据执行模式吸收研究者见解，已有观点直接使用，无需重复索取。研究者原话与 Agent 的解释、疑问和延伸分别保存；不要将 Agent 生成的启发放入“我的理解”冒充研究者观点。

## 输出与更新

默认更新上述目录中的同一份 `paper.md`；用户明确指定其他文件布局时遵循其约定。

标题使用论文名称。保留以下八部分，随材料适度合并短条目：

1. **研究定位**：任务、针对的问题与主要方法范式，简短说明。
2. **核心模型机制**：整体数据流、模块协作与必要训练目标；末尾单列“消融观察”，概括变体、结果和判断边界。
3. **值得关注的设计**：具体特殊之处、设计理由与证据；首次为初步判断，后续结合研究者观点重新审视，不重复抄写模块介绍。
4. **可迁移的方法思想**：可借鉴的机制、成立条件与尚未验证之处；随研究者启发重新分析，保持论文机制与迁移设想的区分。
5. **局限与潜在问题**：只保留影响理解或迁移的主要限制，区分原文与分析。
6. **我的理解与研究启发**：研究者原始观点；未提供时仅注明“待研究者补充”。
7. **Agent 对研究者见解的分析**：有人工观点时分析依据、条件与疑点；未提供时仅注明“待研究者观点后补充”。
8. **知识库关联**：仅链接已存在且实际相关的论文、机制或 Idea；没有时省略此节，不预建空白知识页。

普通论文主体可先以约 600～1000 中文字为目标，不计人工原话；简单论文可以更短，关键复杂机制允许合理展开。优先删除重复背景、完整指标表和泛泛评价，保留关键连接、成立条件与证据。用户只询问某个模块时直接回答该部分，不强制输出整卡。

交付前核对模型连接、消融变体与结果方向、关键定位、事实与推断的边界、人工原话是否完整保留，以及 PDF 链接是否有效。再次分析时确认第3、4、7节已被审视且相互一致。文件已保存时，聊天只报告路径、主要发现或变化及必要缺口，不再重复全文。
