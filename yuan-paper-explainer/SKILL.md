# 参考论文说明

让后续研究能够准确理解论文模型、识别值得借鉴的设计，并按证据位置回查原文。默认面向下一 POI 推荐及相关图、超图、知识图谱方法，用户指定其他领域时按论文实际内容分析。

## 任务分流与研究者参与

| 当前任务 | 读取、分析与产出 |
| --- | --- |
| 局部问答 | 按问题读取相关说明或原文，直接回答；未要求更新时不重写整卡，不为回答问题创建目录。 |
| 首次生成 | 阅读原文并完成模型、消融和机制分析，先交付初稿；第3、4节为初步判断，第6节留给研究者，第7节按已有人工观点分析，没有则留占位。 |
| 补充后再分析 | 重新读取整份 `paper.md`，理解第6节的新观点，按疑点定向回查原文；重新审视第3、4、7节，必要时修正第2、5节。不能只追加第7节，也不强行改动仍成立的判断。 |

已有人工观点直接使用，不重复索取；没有则不阻塞初稿。研究者原话与 Agent 分析分别保存，不擅自改写、覆盖原话，也不将 Agent 启发填入人工区域。观点与原文不符时在 Agent 分析中说明依据，不将研究设想写成论文事实。

再次分析优先更新同一文件的相关内容，在文末简记重要判断的变化、原因与日期，不重读无关材料、生成平行版本或记录每次措辞调整。已明确持续维护的说明，收到新的见解后按更新任务处理，无需反复要求“保存”。

首次保存时简记“初稿，待研究者补充”；结合实际见解完成再次分析后注明状态和日期。两阶段完成后才可进入机制库，不能以标题非空、占位文字或状态字符串代替实质分析。后续见解变化时重新分析，旧状态不足以证明最新内容已就绪；本 Skill 不在初稿阶段生成机制卡。

## 工作目录与论文材料

保存文档时使用用户指定或当前会话已明确的研究工作目录；未明确时询问保存位置，不能把 Skill 源码仓库当作研究目录。

默认结构为 `工作目录/references/论文标题/`，其中 `paper.md` 为唯一主说明，`paper.pdf` 为原文副本。目录不存在时创建；标题仅清理不适合路径的字符，过长时适度缩短。同名不同论文再补作者或年份。

- 先根据已有来源记录中的 Zotero 条目 key、DOI 或标题查找同一论文，命中后复用目录与说明。已知有旧说明时一并核对，避免因标题差异另建一份；需要调整旧布局时保留人工内容并修正相关链接。
- 从用户 PDF 或 Zotero 附件复制原文，不移动或修改源文件；已有同版本 PDF 时复用。版本不同或无法确认时先说明差异，不静默覆盖。
- 说明开头仅保留发表期刊／会议及年份、状态及日期，以及 `[原文 PDF](paper.pdf)`。默认不列作者、Zotero 标识、DOI、卷期或文章编号；身份核对时仍可使用这些信息。只有版本差异影响理解时才补充版本说明。复制后确认文件可读；无法取得 PDF 时如实注明缺失，不生成虚假的本地链接。

## 读取与证据

- 优先使用用户提供的原文和可信提取结果；确认论文版本。旧笔记与研究者观点作为线索，模型事实回到原文核实。
- 先定位方法、框架图、关键公式及消融实验；背景与其他实验仅在解释模型或判断消融所需时读取。不重复生成全文翻译或完整实验综述。
- PDF 可先提取文本；结构、公式或表格有歧义时查看相关页面。局部读取不能省略关键分支、训练目标或决定模块作用的内容。
- 关键模型说明和消融判断附近保留章节、图、表或公式定位；有可靠页码时区分 PDF 页与印刷页。不得猜测页码、数值或未提供的模块。
- 若只有摘要或局部材料，明确说明范围，仅输出可支持的部分和关键缺口；不要补齐未知架构。无法访问原文时说明缺少什么材料。

## 分析流程

### 1. 客观模型还原

用一行或极短段落概括“输入 → 处理与分支 → 交互或融合 → 预测输出”，不提前复述各模块细节；并行模块不要强行写成串行。

整体数据流之后，按模型实际逻辑分模块展开，以“输入与具体处理 → 捕捉的信息或关系 → 输出及后续去向”解释运作过程，不能只罗列模块名称和功能口号。交代模块之间如何连接、交互或融合，以及训练目标如何作用于它们。

图或超图是关键时，分别说明各图的节点对象、边／超边的分组依据与构造步骤、关系所表达的信息，以及节点—边／超边间如何传播、表征送往哪里。必要时说明这种构造是否保留顺序、方向等关键关系；不能把共现关系直接当作时序转移。

按设计价值分配篇幅：图构造、特殊编码器、独特交互等关键机制展开，共用处理与常规步骤合并说明。普通投影、拼接、归一化、分类头和优化器不逐项展开，除非它们决定关键连接或构成特殊设计。公式与符号只保留理解机制所必需的部分；相似通道只讲共同流程和实际差异，避免反复澄清并不存在的误读。

原文未交代的构造或连接当场简记，不用合理猜测补齐；影响理解或借鉴的主要疑点集中在第5节，不在各模块反复展开评议。

### 2. 消融实验

先核对各变体实际删除、替换或改变了什么，以及比较条件；输出直接从贡献判断切入，默认用一至两个短段落（通常约 200～350 中文字，可按证据复杂度调整）。不先枚举变体目录，不用结果表或逐项列表复述数值；只选会影响借鉴取舍的发现与判断边界，不逐项评论所有消融。

- 围绕证据回答：哪些模块或路径贡献较明确；哪些设计增益有限、不稳定或移除后反而改善；作者重点强调的设计是否得到针对性的消融支持。这些判断如何影响优先借鉴什么、谨慎看待什么？不必强行为每个模块排序，也不为填满类别而找出“无效模块”。
- 保留表号和必要的比较条件；只在支撑或改变判断时引用少量关键数字。数值变化需说明方向，百分比与百分点不要混用。
- 删除整条路径与替换单一小模块的改动范围不同，不能仅按降幅排出统一重要性次序。联合移除多个设计不能分配各自贡献；缺少独立消融时简述无法单独判断。未报告显著性时不使用统计显著或无差异的结论。
- 消融反映所测试架构与条件下的表现，不能单凭性能下降证明作者解释的作用机制，也不能把小幅贡献直接称为无效。
- 未提供消融时简述“未见可用消融证据”，不自行推演结果。

### 3. 识别与抽象

从实际结构和消融中选择少量值得关注的设计，说明“针对什么问题 → 具体改变什么 → 如何发挥作用 → 证据与限制”。区分作者的解释和 Agent 的分析；反事实推断写成推断。

抽象时保留具体建模对象、关系语义或信息组织方式，避免只有“捕获高阶关系”“融合多源信息”等泛泛表述。指出可保留的思想、可改变的实现和必要条件。

没有用户研究基座时，将迁移方向写为条件性设想，不强行设计新框架。作者宣称创新、论文具体特点和领域新颖性分别判断；未做相关工作核验时不宣称领域首次。

## 输出与更新

默认更新上述目录中的同一份 `paper.md`；用户明确指定其他文件布局时遵循其约定。

首次生成完整说明时读取 [assets/paper.md](assets/paper.md)，按模板填写；模块名称与数量随论文调整，删除填写提示，不把骨架当作完成的说明。再分析沿用已有文档，仅修改相关部分，不以模板覆盖研究者内容；局部问答不加载模板。

标题使用论文名称。完整说明以第1—7节为主结构，第8节仅在有实际关联时保留：

1. **研究定位**：任务、针对的问题与主要方法范式，简短说明。
2. **核心模型机制**：先整体数据流，再展开关键模块、信息关系与必要训练目标；末尾单列“消融判断”，说明贡献、重点设计的证据与借鉴取舍。
3. **值得关注的设计**：具体特殊之处、设计理由与证据；首次为初步判断，后续结合研究者观点重新审视，不重复抄写模块介绍。
4. **可迁移的方法思想**：可借鉴的机制、成立条件与尚未验证之处；随研究者启发重新分析，保持论文机制与迁移设想的区分。
5. **局限与潜在问题**：通常保留2～3个直接影响模型理解、模块借鉴或证据判断的主要问题，每项简述问题及影响，区分原文与分析。无需罗列复现审查清单；没有涉及的社交、文本等信息源，以及与当前任务无关的通用部署限制不默认纳入。数值冲突可简记一句，已有消融边界不重复展开；问题少时不凑条数。
6. **我的理解与研究启发**：研究者原始观点；未提供时仅注明“待研究者补充”。
7. **Agent 对研究者见解的分析**：有人工观点时分析依据、条件与疑点；未提供时仅注明“待研究者观点后补充”。
8. **知识库关联**：仅链接已存在且实际相关的论文、机制或 Idea；没有时省略此节，不预建空白知识页。

不设整卡统一字数目标。第2节的模块说明（不含消融）对多模块论文可参考约1100～1300中文字，第5节通常约200～300中文字；均为压缩参考，不是必须填满的配额或硬性上限，简单论文更短，关键复杂机制按需展开。第3、4节只增加设计选择与迁移认识，不重复模块过程。压缩时先合并常规操作、重复数据流、结果复述和跨章节重复，保留关键构造、连接与证据，不把方法说明扩展为全面审稿。

交付前核对模块构造和输出去向是否讲清、消融判断是否回应重点设计且有证据、关键定位、事实与推断的边界、人工原话是否完整保留，以及 PDF 链接是否有效。再次分析时确认第3、4、7节已被审视且相互一致。文件已保存时，聊天只报告路径、主要发现或变化及必要缺口，不再重复全文。
